# IPL Ticket Booking

A simple React app following the supplied project steps: navbar and pages, match cards, a booking form, booking history, and filtering by venue.

The fixture dates in `src/data/matches.js` are examples, not confirmed IPL details. Stand prices follow the requested rates: General ₹500 and VIP ₹1,500 per ticket.

## Run the app

```sh
npm install
npm run dev
```

Without Supabase settings, bookings are saved in this browser's local storage.

## Connect Supabase

This project uses `public.bookings`; the setup below uses `CREATE TABLE IF NOT EXISTS`, so it will not create a duplicate. The app keeps the existing LocalStorage fallback when Supabase is not configured.

1. In Supabase **Authentication → Providers**, enable the Email provider and configure email confirmation. Keep Anonymous Sign-Ins enabled while existing guest sessions are being upgraded. Enable **Allow manual identity linking** to let existing anonymous users attach an email or Google identity without changing their user ID.
2. In **SQL Editor**, run this setup. It creates the table only if missing, adds the ownership column required by Row Level Security, removes existing permissive frontend policies, and grants only the operations the app needs. The policy cleanup does not delete booking rows, but it replaces permissive policies applying to `public`, `anon`, or `authenticated`:

   ```sql
   create table if not exists public.bookings (
     id bigint generated by default as identity primary key,
     name text not null,
     tickets integer not null check (tickets > 0),
     stand text not null,
     venue text not null,
     place text not null,
     created_at timestamptz not null default now()
   );

   alter table public.bookings
     add column if not exists owner_id uuid references auth.users(id) on delete cascade;

   create index if not exists bookings_owner_id_created_at_idx
     on public.bookings (owner_id, created_at desc);

   alter table public.bookings enable row level security;

   revoke all on table public.bookings from public, anon, authenticated;
   grant select, insert on table public.bookings to authenticated;

   do $$
   declare
     existing_policy record;
   begin
     for existing_policy in
       select policyname
       from pg_policies
       where schemaname = 'public'
         and tablename = 'bookings'
         and permissive = 'PERMISSIVE'
         and roles && array['public', 'anon', 'authenticated']::name[]
     loop
       execute format(
         'drop policy %I on public.bookings',
         existing_policy.policyname
       );
     end loop;
   end
   $$;

   create policy "Bookings owner insert"
     on public.bookings for insert to authenticated
     with check (
       owner_id = (select auth.uid())
       and (select auth.jwt() ->> 'is_anonymous') = 'false'
     );

   create policy "Bookings owner select"
     on public.bookings for select to authenticated
     using (
       owner_id = (select auth.uid())
       and (select auth.jwt() ->> 'is_anonymous') = 'false'
     );
   ```

   Existing rows are not deleted or reassigned. Anonymous users cannot use the app's booking policies; converting a guest session through email verification or Google identity linking preserves its user ID and its existing bookings. Existing rows without an `owner_id` remain inaccessible. The migration removes permissive policies applying to frontend roles; any remaining restrictive policies can further limit access and should be reviewed if requests are denied.
3. Use the project's **Project URL** and **publishable** API key. The local `.env` file is already configured for this project. For another environment, copy `.env.example` to `.env` and set:

   ```env
   VITE_SUPABASE_URL=https://your-project-id.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
   ```

4. Configure Supabase **Authentication → URL Configuration**:
   - Set **Site URL** to your production app origin.
   - Add `http://localhost:5173/auth/callback`, `http://localhost:5173/reset-password`, `http://127.0.0.1:5173/auth/callback`, and `http://127.0.0.1:5173/reset-password` to the redirect allow list for local development.
   - Add your production `/auth/callback` and `/reset-password` URLs to the allow list.
5. To enable Google sign-in:
   - In Google Cloud Console, configure the OAuth consent screen and create an OAuth client ID of type **Web application**.
   - Add your app origins (local development and production) as authorized JavaScript origins if required by the console.
   - Set the authorized redirect URI to `https://mxravwkidkkocvzhuysw.supabase.co/auth/v1/callback`.
   - In Supabase **Authentication → Providers → Google**, enable Google and enter the Google client ID and client secret. Keep the client secret only in Supabase; never put it in `.env` or frontend code.
6. Restart `npm run dev`. New bookings are saved to Supabase with the authenticated user's ID as `owner_id`. Booking History retrieves only that user's bookings and filters by venue. Match/date and pricing details are derived from the app's fixture and stand-price data.

Only use the publishable key in this frontend app. Never put a `service_role` or secret key in a Vite environment variable; Vite exposes `VITE_*` values in client code. Supabase requires an anonymous user to verify an email before setting a password; the app asks the user to set the password after returning from that verification link. Signing in to an unrelated existing account does not transfer guest bookings.
